# .stlog v2：多文件规则

> **状态：已实现（0.8.3）；绘图部分未实现。** v1.4 单文件仍是合法输入，见
> [stlog-format.md](stlog-format.md)；版本演进见 [CHANGES.md](CHANGES.md)。
>
> v2 只改**物理组织**——一个会话从"一个文件"变成"一个目录：入口 + 设置 + 索引 + 若干包"。
> **不改记录格式与页格式**：每个包内部仍然是 v1.4 的 16 KB 头 + 4 KB 定长页 + 整页 CRC。

---

## 0. 目标 / 非目标

**目标**

- 单文件不再无限增长：包有上限，写满**自动新建下一个包**，不会因为"文件太大"停录
- 打开成本与总大小无关：读 manifest + 需要的包，不再整份扫描
- 元数据与数据分离：可变的只有 manifest，数据包只追加、永不改写
- 索引是纯缓存：删掉能重建，损坏不影响正确性
- 每个包自描述：manifest 丢了也能按包认领

**非目标**

- **禁止跨包续片**：一帧的所有分片必须落在同一个包里（**允许跨页**）
- 不做压缩、加密、多写入者、远程写入
- 不做 v1.4 单文件 → v2 目录的自动迁移

## 1. 术语

| 术语 | 含义 |
|---|---|
| 会话 | 用户视角的一段录制；v2 里等于一个目录 |
| 包（package） | 一个 `pkg-NNNN.stlog`，是**完整合法的 v1.4 文件**，有大小上限 |
| 入口（manifest） | `manifest.json`，只做连接：会话身份 + 目录内文件清单 |
| 设置（settings） | `settings.json`，端口 / 模式 / 标签 / 绘图等所有会变的设置 |
| 索引（index） | `index.bin`，纯缓存，可删可重建 |
| 帧 | 一条逻辑数据（一次收/发事件）；包内可跨页，**不可跨包** |

## 2. 目录布局

```text
20261030_104512_ab12cd34/        ← 会话目录，命名规则见 §2.1
  manifest.json                  ← §7.1 工程入口，仅做连接
  settings.json                  ← §7.2 业务设置（端口 / 模式 / 标签 / 绘图…）
  index.bin                      ← §8 索引缓存，可删
  pkg-0001.stlog                 ← §3 数据包，完整 v1.4 文件
  pkg-0002.stlog
```

### 2.1 目录名

```text
yyyyMMdd_HHmmss_<id8>            例：20261030_104512_ab12cd34
```

| 段 | 取值 | 理由 |
|---|---|---|
| `yyyyMMdd_HHmmss` | 建会话时的本地时间，**秒**精度 | 资源管理器按名排序即按时间排序；到秒是因为目录会长期保留，同一分钟建两个必须分得开 |
| `id8` | `sessionId`（uuid）前 8 位 | **身份**。进程号会随 daemon 重启重排，跨天恢复或换机器都会撞；uuid 不会 |
| 连接符 | `_`，全 ASCII | 无空格无中文，各平台都能直接引用，脚本里免转义 |

- 长度 24 字符，离 260 路径限制很远；撞号（`id8` 相同，概率约 4e-9）追加 `-2`、`-3`，
  **不改时间戳**——改了就和"创建于什么时候"对不上
- **不带端口 / 模式**：转发模式有两个口、录到一半 `SwitchPort` 会换口、`COM4` 换台机器
  就没有意义。这些信息放 `manifest.label`，只用于界面显示
- **目录名可以改**：会话身份是 `manifest.sessionId`，不是目录名。GUI 打开时读
  `manifest.json`，不靠目录名匹配；"最近工程"存 `(sessionId, path)`，路径失效时按
  `sessionId` 重新认领。改名不影响读取，也不影响包的自描述性（§3）
- 改名可以把时间 / id 段整个丢掉（用户改成「温度采集」也合法），同一父目录下的
  唯一性由文件系统保证

### 2.2 目录内容约束

- 包名固定 `pkg-%04d.stlog`，从 `0001` 起连续；**跳号即缺包**（§11）
- 目录里只应有这四类文件：`manifest.json`、`settings.json`、`index.bin`、`pkg-*.stlog`；
  发现陌生文件**不删、不猜、不参与解析**，只记日志
- 将来若要再加一类文件，**先在本规范里定义清楚再加**，否则会被当成陌生文件

### 2.3 谁来打开

- **工程 = 一个能继续用的会话**：GUI 打开工程目录时走 `session.open`，守护进程把它
  恢复成一个真实会话页（单端口 / 转发，模式取自 `settings.json`），历史由这个进程的
  共享环提供，页面可以继续收发。所以工程目录**必须有守护进程**，离线时明确拒绝
- **单个 `.stlog` = 只读浏览**：守护进程不接受包文件（没有 `settings.json`、没有
  `index.bin`，也不会再追加），GUI 用本地文件页打开，离线可用
- **CLI**：`session-open <工程目录>` 交给守护进程；`stlog-*` 四条离线读写，工程目录
  与单文件都收
- 端口：`settings.json` 记了端口就按「已声明」建进程（会话页显示 `COM8 @ 115200`），
  没记就建空闲进程让用户自己选 —— 不拿目录名冒充串口名

## 3. 包

每个包是一个**完整合法的 v1.4 文件**：

- 16 KB 固定头：槽 A/B（各 4096 B）+ 影子 A/B（各 4096 B）
- 记录区从 `0x4000` 起，4096 B 定长页；页头 20 B + 统计块 44 B + 页尾 CRC 4 B
- 帧可在**包内跨页**：`dir` bit7 续片链 + 页头 `firstRecOff`（`0xFFFF` = 整页无帧头）

与 v1.4 的差异只有三条：

| 项 | v1.4 | v2 的包 |
|---|---|---|
| 记录区上限 | `max_size_mb`，满了**停录** | `pkgMaxBytes`，满了**切包** |
| 槽内字段 | uuid / created / … | 追加 `sessionId`（同 uuid）与 `seq`（包序号） |
| 角色 | 单文件即整个会话 | 只是会话的一段，但**自描述**：单拎出来也能读 |

## 4. 包上限与切包（核心规则）

### 4.1 参数

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `pkgMaxBytes` | **64 MiB** | 8 MiB – 1 GiB | 单包上限；16 KB 头占比 @64 MiB ≈ 0.025% |
| 页对齐 | 4096 B | 固定 | 包大小永远是 16 KiB + 4096 的整数倍 |

### 4.2 准入（写一帧之前）

```text
entryCost = 12 + len(payload) + (origin == inline ? 1 + len(originStr) : 0)
剩余       = pkgMaxBytes - 当前已分配（按页向上取整）

if entryCost > 剩余:
    封包(); 开新包()

if entryCost > pkgMaxBytes:          // 软上限：帧比包还大
    本包只装这一帧，包大小 = 16 KiB + align4096(entryCost)

写入（包内允许跨页）
```

### 4.3 三条硬规则

1. **切包只在帧边界**：绝不把一帧切开跨包；宁可提前封包留空。
2. **允许跨页**：包内仍按 v1.4 的分片规则，`dir` bit7、`firstRecOff`、`0xFFFF` 全不变。
3. **软上限**：单帧超过 `pkgMaxBytes` 时该帧独占一个包，包大小临时超过上限。
   "帧比包大"不能变成丢数据（与 v1.4 不限制最大帧的原则一致）。

### 4.4 空间浪费上界

| 情况 | 浪费 |
|---|---|
| 常规切包 | ≤ 最大帧 − 1（400 B 帧 @64 MiB ≈ 0.0006%） |
| 软上限包 | 整包一帧，浪费 = 页对齐余量（≤ 4095 B） |
| 空包（崩溃在建包与首帧之间） | 16 KiB，见 §11 |

## 5. 写入顺序与崩溃语义

```text
建包    写 16 KiB 头（槽里带 sessionId + seq）  → fsync
追加    每 flush 写一页（整页 4096 B；首次写不写影子，重写才写）
封包    尾页整页写 + 整页 CRC（+ 影子）          → fsync
登记    更新 manifest + index（tmp + rename）——**只在切包/关包/关会话时**
```

崩溃点：

| 崩在 | 磁盘状态 | 恢复 |
|---|---|---|
| 建包头之后、首帧之前 | 空包（`rec=0`） | 扫到时报"空包"，可删；不影响其它包 |
| 追加过程中 | 尾页 CRC 坏 | v1.4 双影恢复；救不回则丢该包尾部（其余包完好） |
| 封包后、manifest 之前 | 孤儿包 | §6 认领 |
| manifest 写入中 | 残留 `.tmp` | 忽略 tmp，用旧 manifest；**以包为准** |

## 6. 孤儿包与 manifest 丢失

```text
扫目录 → 每个 pkg-*.stlog 读 16 KiB 头，取 (sessionId, seq)
按 sessionId 分组，组内按 seq 排序

manifest 存在 → 以磁盘包为准补登记；manifest 里指向不存在包的条目删除并记日志
manifest 缺失 → 用磁盘包重建（label / notes 丢失，其余不丢）
seq 重复     → 保留 created 较新者，另一个改名 pkg-NNNN.stlog.dup，**不删**
```

**不变量**：`manifest.json` 和 `index.bin` 里的一切都能从包重建，
**除了 `settings.json` 里的 `label` / `notes` / 绘图配置这些人工内容**。

## 7. 入口（manifest.json）与设置（settings.json）

两个文件刻意分开：

- **`manifest.json` 仅做连接**：只放会话身份和「目录里有哪些文件」。改设置永远不会
  碰它，将来加一类新设置也不会让它变大。
- **`settings.json` 放所有会变的业务设置**。加绘图配置直接往 `plot` 里塞，不动入口。

### 7.1 manifest.json

```json
{
  "v": 1,
  "sessionId": "ab12cd34e5f60718293a4b5c6d7e8f90",
  "created": "2026-10-30T10:45:12+08:00",
  "files": {
    "settings": "settings.json",
    "index": "index.bin",
    "packages": [
      { "seq": 1, "file": "pkg-0001.stlog", "bytes": 67108864, "sealed": true },
      { "seq": 2, "file": "pkg-0002.stlog", "bytes": 12349440, "sealed": false }
    ]
  }
}
```

规则：

- **只在切包 / 关包 / 关会话时写**，不随 flush 写
- 原子写：同目录 `manifest.json.tmp` → `rename`
- `sealed=false` 只允许出现在**最后一个包**
- 包级的 `frames` / `records` / `firstTs` / `lastTs` **不放这里**：那是缓存，
  放 `index.bin`（§8），坏了能重建
- `seq` 从 1 起连续；跳号即缺包（§11）

### 7.2 settings.json

```json
{
  "v": 1,
  "label": "COM4 ↔ COM14",
  "notes": "",
  "mode": "forward",
  "ports": { "a": "COM4", "b": "COM14", "baud": 115200 },
  "log": "202610301045_3.log",
  "plot": {}
}
```

| 字段 | 说明 |
|---|---|
| `label` | 界面显示名，可空 |
| `notes` | 自由备注 |
| `mode` | `single` / `forward`；缺省按 `single`（早期文件没有这个字段） |
| `ports` | 录制开始时的端口快照；`baud` 为 0 表示未知 |
| `log` | 与之同时录制的那份 `history/*.log` 文件名，便于成对查找 |
| `plot` | 预留给绘图：选中通道、量程、坐标轴、区域、标注。当前只保留结构，不解释内容 |

规则：

- 原子写，同上
- 只在设置变化时写（开始录制、改 label / notes、以后改绘图配置）
- 与包头槽里的 `Settings` 的关系：槽是**冗余自描述**（保证单个 pkg 拎出去也能读），
  `settings.json` 是**权威**；两者冲突以 `settings.json` 为准

## 8. 索引（可重建的缓存）

- 文件：`index.bin`；**删掉或损坏 = 变慢，不是错误**，任何情况下不因为索引拒绝打开会话
- 内容（当前实现到包级，页级留到需要时再加）：
  - 头部 16 B：magic `SLIX` / ver / 条目数
  - 每包 64 B：`seq / bytes / frames / records / firstTs / lastTs / mtime / sealed`
- 失效判定（任一命中即整份丢弃重建）：magic/ver 不符、条目数与 manifest 不符、
  包文件大小与 `bytes` 不符、包 mtime 与 `mtime` 不符
- 写入时机：关包 / 关会话时，与 manifest 同批
- 构建：全扫一遍（64 MiB 约 50–80 ms，含每页 CRC）；也可后台构建，先读后到

## 9. 读取顺序

```text
打开会话
  1. manifest（缺失/损坏 → §6 认领）
  2. index（失效 → 扫包重建）
  3. 按需只读目标包的必要页

跳到 ts=T
  包级索引定位包 → 页级索引定位页 → 从该页起读

缺包
  列表在缺号处插一条「缺包 seq=N」，不静默跳过
  **不做跨包拼接**（帧不跨包，本来也不需要）

导出
  按 seq 顺序逐包导出；每包的帧都是完整的
```

## 10. 删除与保留

- 只能删**已封包**；正在写的包永不删
- 删除 = 删文件 → 更新 manifest → 索引失效（下次重建）
- `keep_days` 按包内 `lastTs` 判断，整天为单位
- 全部包删光：目录只剩 manifest（空壳）；要么保留，要么整个目录删——两种都合法

## 11. 失败模式

| 场景 | 行为 |
|---|---|
| 包写失败（磁盘满 / EIO） | 停录 + 事件；**已封包的包仍可读** |
| 封包失败 | 同上；该包 `sealed=false`，下次打开按截断恢复 |
| manifest 写失败 | 继续录（包为准），记 WARN，下次切包重试 |
| 索引损坏 | 静默重建，不报错 |
| 缺包（seq 跳号） | 会话继续；列表标「缺包」；导出跳号 |
| 孤儿包 | 认领并补登记 |
| seq 重复 | 保留较新者，另一个改 `.dup`，不删 |
| 单帧 > 包上限 | 软上限：该帧独占一包（§4.3） |
| 包内帧跨页 | 正常路径（v1.4 分片） |
| 包头损坏（16 KiB 全坏） | 该包作废并标记；其余包不受影响 |

## 12. 与 v1.4 的差异清单

| # | 项目 | v1.4 | v2 |
|---|---|---|---|
| 1 | 会话载体 | 一个 `.stlog` 文件 | 一个目录（manifest + 包 + 索引） |
| 2 | 大小上限 | `max_size_mb`，满了停录 | `pkgMaxBytes`，满了切包 |
| 3 | 记录区起点 | `0x4000` | 不变（每包都有 16 KB 头） |
| 4 | 跨页 | 允许（`dir` bit7 续片链） | 不变 |
| 5 | 跨包 | 不存在 | **禁止**（§4.3） |
| 6 | 元数据 | 文件头槽 A/B | `settings.json` 权威，槽冗余自描述 |
| 7 | 打开成本 | O(整个文件) | O(manifest + 需要的包) |
| 8 | 索引 | 无（全扫） | 可重建的 `index.bin` |
| 9 | 删除旧数据 | 重写大文件或不删 | 删整包 |
| 10 | 崩溃影响面 | 尾部一页 | 尾部一包 |

## 13. 待定

- `pkgMaxBytes` 默认 64 MiB 是否合适（包数 vs 单包打开时间）
- 索引放会话目录，还是塞进包的尾部（少一个文件，但会让包不再"只追加"）
- 空包（`rec=0`）是自动删除还是保留待查
- 绘图配置已定为 `settings.json` 的 `plot` 字段（跟随会话，见 §7.2）。若将来要做
  「一篇图引用多个会话」，再另立独立文档格式（如 `.stplot` + 外部引用）
- v1.4 单文件的自动命名是 `yyyyMMddHHmm_<进程号>.stlog`（见 `daemon/history.go`），
  与本规范的目录名格式不一致——是否统一到 `yyyyMMdd_HHmmss_<id8>`，还是各管各的

## 14. 兼容

- v1.4 单文件仍是**合法输入**：按"只有一个包的会话"打开，manifest 在内存里合成
- GUI 的拖放：拖入**工程目录**或 `.stlog` 文件（含目录里的单个 `pkg-NNNN.stlog`）
  都能直接打开；识别不了的路径汇总成一个警告窗，由 `App.ProbeDroppedPaths` 判定
  （前端拿不到 stat，分不清"目录"和"无扩展名的文件"）
- 不做自动转换；需要归档时提供 `stlog pack <file> <dir>` 显式转换
- 反向（v2 → 单文件）不提供：单包可直接拷走，本身就能读
