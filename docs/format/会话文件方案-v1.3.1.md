## 0. 目标 / 非目标

**目标**

1. 一个开启记录的标签/会话 = 一个 `.stlog` 文件；关闭记录保留文件，再开续写同一文件。
2. 离线（守护进程未运行）GUI 拖入文件即只读打开：分页、搜索、导出。
3. 推送是**手动**动作：把文件与会话设置的所有权移交给守护进程；之后 GUI 只经 IPC 操作。
4. 同一文件**写者唯一**；读者可并发（含杀毒/备份/我们自己的导出）。见 §3。
5. 导出 `log`（文本行）/ `txt`（解码文本）/ `csv`（结构化列）。
6. 新建会话支持「由文件开始（续写同一文件）」与「离线读取文件（只读）」。
7. **设置可恢复**：任一槽完好 ⇒ 拿到一份完整自洽的设置；不出现"半个状态"。

**非目标（v1 不做）**

- 自动推送（守护进程启动不接管已有本地标签）；拖入是否直接推送由 `drop_action` 设置决定。
- 每标签默认录制：默认仍是"不记录、不建文件"。
- 远程守护进程、数据库、压缩/加密、跨文件全局索引、多文件合并。
- 旧 `history/*.log` 的写入与转换（只读兼容）。
- **sidecar 索引文件**（打开时扫描建内存索引，见 §2.8）。
- **追加式元数据变更日志 / 头部压缩**（头部是全量快照，见 §2 开头的取舍说明）。
- **文件预分配、mmap 写入、压缩卷/EFS/网络盘上的写模式**（见 §2.7、§3）。

**三条贯穿全局的原则**

1. **磁盘友好**：稳态零 fsync；**满页写**时天然 4 KB 对齐；写调用次数越少越好。
   `flush_max_ms` 触发的小写会破对齐，那是"用写放大换延迟上界"的自觉代价（§2.7 第 2 条），
   不是意外——文档里不承诺"每次 write 都对齐"。
2. **记录区除最后一页外只追加**：最后一页允许在持写锁时整页重写，且**已提交前缀必须从磁盘重读、
   逐字节原样写回**（§2.7 第 4 条）。这是"尾页重写不丢已提交数据"的唯一依据。
3. **不猜**：任何读不懂的元数据都按"该槽作废/该记录停止"处理，绝不靠启发式补齐；
   唯一例外是 `originId` 查不到字典——那种情况显示 `unknown(id=N)`，因为数据本身没坏（§2.6）。

## 1. 术语与所有权

| 实体 | 谁持有 | 说明 |
|---|---|---|
| 文件（磁盘） | 无人 / GUI / 守护进程 | **写者唯一**；读者可并发（§3） |
| 槽 slot | 文件内两页 | 每槽一份**完整设置快照**，seq 大者生效（§2.4） |
| 尾页 tail page | 含最后一条完整记录的 4 KB 页 | 唯一允许重写的页（§2.7） |
| 本地文件标签 `local-file` | GUI 进程内 | 只读，不经过守护进程 |
| 会话 session | 守护进程 | `kind=live`（有进程写）或 `kind=replay`（只读） |
| 会话设置 | 推送后：守护进程 | 端口参数、模式、记录开关、文件参数 |
| 界面设置 | 永远 GUI | 主题、字体、比例、语言、hex 样式、`drop_action` |

GUI 的 `settings/gui.ini` 只存界面设置；守护进程的 `settings/daemon.ini` 存 `[storage]` 默认值与
最近一次会话参数；文件槽里存当前设置快照（含创建时的参数）。

## 2. 文件格式（字段级）

**头部为什么用"全量快照"而不是"追加式变更日志"**（v1 → v1.2 的取舍，之后沿用）：

| 维度 | 追加式日志 | 双槽全量快照 |
|---|---|---|
| 恢复语义 | 坏 entry 之后全部丢失，需"立即压缩"补救 | 任一槽有效即完整；不存在半个状态 |
| 掉电写序 | 依赖补丁先后顺序，补丁丢了状态就错 | **快照自带全部状态，写回乱序无害** |
| 每次元数据修改 | 复制整区（7936 B）+ 翻 superblock，2 次 write | **覆盖一整页 4096 B，1 次 write** |
| 可合并 | 中间 entry 不能随便丢 | **只关心最终状态，合并天然正确** |
| 结构 | entry 类型/序号连续性/压缩触发/坏 entry 修复 | 无 |

代价：单次写入固定 4 KB（比"追加一条 40 B entry"贵），靠"元数据低频 + ≤1 次/秒合并 + 内容去重"兜住（§2.5）。

### 2.1 布局（固定 8 KB 头）

```
0x0000  槽 A    4096 B（一整页）  ┐ 两份完整快照，seq 大且校验通过者生效
0x1000  槽 B    4096 B（一整页）  ┘ 写时总是覆盖"较旧"的那一槽
0x2000  记录区起点（固定 8192，4 KB 对齐）
```

- 没有 superblock、没有 `recordsOffset` 字段、没有 `header_kb`：**记录区起点是格式常量 0x2000**。
  好处是"槽全坏也不影响找回记录"——直接按 0x2000 开始逐条扫描即可（§2.9、§10）。
- 两槽各占一整页：写 A 不会连带弄脏 B 所在页，避免页内读改写（RMW）。
- 头部固定 8 KB，比 v1.1 的 16 KB 省一半，短会话占比因此减半。

### 2.2 槽格式（4096 B）

```
0x0000  magic          "SLOG" u32
0x0004  slotVersion    u16 = 1         ← 格式版本（槽布局）；更高版本 → 该槽无效
0x0006  flags          u16 = 0         ← v1 必须为 0，未知位 → 该槽无效
0x0008  seq            u64 LE          ← 唯一决定新旧
0x0010  ts             u64 LE          ← Unix ms，仅展示 + seq 并列时 tie-break
0x0018  len            u16 LE          ← payload 字节数，≤ 4000
0x001A  reserved       [6] = 0
0x0020  payload        [len] UTF-8 JSON ← 内部 `v` 是 payloadVersion（§2.3）
0x0020+len      crc32        u32 LE    ← 覆盖 0x00..0x1F + payload（含 len 自身）
0x0024+len      endMagic     "ELOG" u32
填充            0x00 直到 0x1000（整页写满）
```

- **`slotVersion` 与 `payloadVersion` 是两个独立版本号**：前者管槽布局（改动就换布局），
  后者管 JSON 字段（只加字段不升版也可以）。v1：`slotVersion == 1`、`payloadVersion == 2`。
- `crc32` 必须覆盖 `len`，否则"长度字段被写坏"这类损坏会绕过校验。
- `endMagic` 用来区分**"被截断"**与**"CRC 错"**：诊断信息不同，排查成本差很多。
- 单槽载荷上限 4000 B（= 4096 − 32 头 − 8 尾 − 56 余量），超了是写入方 bug，不是用户错误。

### 2.3 快照载荷（JSON）

```json
{
  "v": 2,
  "uuid": "3f2a9b1c",
  "created": "2026-10-29T14:40:01+08:00",
  "app": "0.8.3",
  "port": "COM12", "baud": 115200, "dataBits": 8,
  "stopBits": "1", "parity": "none", "flow": "none",
  "mode": "single", "portB": null, "baudB": null,
  "encoding": "utf-8",
  "label": "COM12 @ 115200",
  "notes": "",
  "record": true,
  "origins": ["gui-a3f1", "cli-7b2c"],
  "stats": {"entries": 123456, "lastTs": 1730000000000}
}
```

| 字段 | 可变 | 约束 |
|---|---|---|
| `v`（payloadVersion） | 否 | == 2；更高版本 → 该槽无效 |
| `uuid` / `created` / `app` | 否 | 必须存在；`created` 为 ISO-8601 带时区 |
| 端口参数（`port/baud/…/baudB`） | 是 | 重连、换端口、改参数后更新 |
| `label` | 是 | ≤ 256 B（UTF-8），写入前校验 |
| `notes` | 是 | ≤ 1 KB，写入前校验 |
| `record` | 是 | 当前是否在记录（仅崩溃后供人参考，不驱动自动恢复） |
| `origins` | **只追加** | 位置数组，id = 下标 + 1；不重排、不删除；追加时去重；**每个元素 ≤ 64 B** |
| `stats` | 是 | **仅** 关闭 / 推送移交前写；不允许定时写 |

**`origins` 的容量规则（两条上限，取小者）**

- **硬上限 254 条**：`originId` 是 u8，255 保留给"内联回退"，0 保留不用（§2.6），所以 id 最多到 254。
- **字节预算 4000 B**：序列化后 `len` 必须 ≤ 4000；追加新来源会超限时同样冻结字典。
- 触发任一上限后：**冻结字典**，此后新来源一律用 `originId = 255` 内联（每条约 +14 B，见 §2.6）。
- 典型容量：base 约 450 B，余量约 3.5 KB；9 字符来源名约 290 个（被 254 条硬上限先卡住），
  16 字符约 180 个（被字节预算先卡住）。
- **绝不删除或重排**字典项：已有记录按 id 引用，删一条会让那些记录永久不可解。
- 同一字符串复用同一 id，不重复占号（追加前查重）。
- 单个元素 ≤ 64 B 与内联上限一致，避免"能进字典的存不下、能内联的进不了字典"这种不对称。

### 2.4 校验与选槽

**读取流程**

```
1. 读 0x0000 与 0x1000 各 32 B（只要槽头），必要时再读整槽
2. 逐槽校验：magic == "SLOG" / slotVersion == 1 / flags == 0 / len ≤ 4000
             / 0x20+len+8 ≤ 4096 / crc32 匹配 / endMagic == "ELOG"
             / payload 能解析成 JSON 且 payloadVersion == 2、uuid 与 created 存在
3. 选槽：两槽有效 → seq 大者；seq 相等 → ts 大者；ts 也相等 → 取 A
         一槽有效 → 用它
         两槽都无效 → 拒绝打开（但记录区仍可从 0x2000 扫描救回）
```

- 选槽规则必须**确定性**，禁止"随机挑一个"或"按文件顺序挑"。
- 校验失败的槽**不修复、不删除**，它保留的是上一次的完整状态，是回退依据。
- 若 `payloadVersion` 比本程序支持的新（例如 3）：该槽无效；两槽都新 → 提示"由更新版本创建"。

**为什么不需要"翻指针"**：写新快照时另一槽仍然完整有效，不存在"指针指向半个区"的中间态；
读取方按 seq 选，写入方按 seq 覆盖（§2.5）。掉电最多让新槽无效，旧槽继续生效。

### 2.5 写槽流程

```
1. 状态 S = 当前完整设置（内存结构体）
2. 序列化 JSON → bytes（≤ 4000；超了就按 §2.3 冻结字典后重试）
3. 去重：若 bytes 与当前生效槽的 payload 逐字节相同 → 直接返回，不写盘、不动 seq
4. target = 两槽中 seq 较小的那个；无效槽优先当 target
5. newSeq = max(有效槽 seq) + 1（都无效则 1）
6. 组装 4096 B 缓冲：头 + payload + crc32 + endMagic，其余补 0
7. 一次 pwrite(4096, target 页)；fsync 仅当 [storage] fsync = true
8. 成功后更新内存里的 seq 与当前状态
```

- **必须整页覆盖（4096 B）**：只写有效长度会留下旧尾巴，逻辑上虽被 `len` 截断，但设备层
  会做"4 KB 读改写"（物理 8 KB），比整页写 4 KB 更贵。
- **不 fsync 也安全**：目标槽写坏 → CRC/endMagic 失败 → 读取方回退另一槽；这与 v1.1
  "先复制区再翻 superblock"等价，但只有一次写。
- **去重为什么重要**：没有它，"打开→什么都不改→关闭"要写两页（置脏 + 置净的等价物），
  与"空会话零写"的语义直接冲突。去重后，状态没变就是零写。
  去重比较的是**序列化字节**，所以字段序列化顺序必须稳定（用 struct 而非 map 承载设置）。
- **合并写入天然正确**：写协程每秒最多落盘一次，期间多次状态变化只写最终状态（全量快照不含历史）。
- 写失败（EIO/ENOSPC）：旧槽仍有效，元数据回退到上一次；记日志、报错、**不停止记录**。

**新来源的落盘顺序（v1.3.1 新增）**

- 新 origin 必须先**同步写快照成功**，才允许写引用该 id 的记录。
- 快照写失败 → 本批记录**改用 `originId = 255` 内联**，绝不使用"还没落盘的 id"。
- 违反这条的唯一后果是"记录引用了一个槽里没有的 id"，所以读取侧仍然必须容错（§2.6），
  但写入侧要尽量让它不发生。

**写入频率约束**：一个会话的元数据写次数 = 开记录(1) + 新来源(每个 1) + 改参数(0–n) + 关记录(1)。
典型 2–4 次 × 4 KB ≈ **8–16 KB/会话**；守护进程侧合并后上界为 **1 次/秒**。
禁止定时写 `stats`、禁止按包更新 `stats`（那会把 4 KB 变成每秒 4 KB 的常流）。

### 2.6 记录格式（区域从 0x2000 开始）

```
记录 = ts u64 LE | dir u8 | len u16 LE（bit15 = 带 origin）| payload[len] | [originId u8 | 内联]
dir: 0=system 1=rx 2=tx 3=P1 4=P2      （0x05..0xFF 保留）
payload: 数据方向 = 原始字节（raw，不存 hex）；system = UTF-8 文本
len ≤ 16384（bit15 留给 origin 标志，15 位 = 32767，这里主动压到 16 KB）
ts: 写入侧强制单调（now ≤ last 时写 last+1），避免 NTP 回跳把按时间分页搞坏
originId: 0 保留不用；1..254 查槽内字典；255 = 内联（originLen u8 ≤ 64 + UTF-8 字符串）
```

**坏记录的判定（读到即停，不猜不跳）**

| 条件 | 处理 |
|---|---|
| `dir ∉ 0..4` | 坏记录，停 |
| `len > 16384` | 坏记录，停 |
| `originId == 0` | 坏记录，停（写入侧永不产生 0） |
| `originId == 255` 且 `originLen > 64` 或不是合法 UTF-8 | 坏记录，停 |
| 载体越界（记录尾超出 EOF） | 尾部半包，停（不是错误） |

**明确不当作坏记录的情况**

- `originId ∈ 1..254` 但当前槽字典里没有这个 id → 显示 `unknown(id=N)`，继续读。
  成因有三种：崩溃前快照没落盘、并发读者看到的是旧槽、两槽全坏走救回导出。数据本身完好，
  不能因为"名字查不到"就把后面的记录全丢掉。
- `ts` 不单调 → 不算损坏（时钟跳变不是数据问题），但**会破坏按时间分页的前提**：
  扫描时把该文件标为 `tsTrusted = false`，分页定位退化为从记录 0 开始线性扫描（结果仍正确，
  只是慢），GUI 在状态栏标注"时间戳异常"。写入侧本来强制单调（§2.6 开头），所以正常文件不会走到这里。
  分页游标本体是**记录序号**，`beforeMs` 只是"时间→序号"的二分提示，见 §5。

**没有填充记录**：v1.2 的 `dir=0x7F` 已删除。页尾未写满的区域由"尾页重写"在下次写入时
整页补零覆盖（§2.7），记录区不再需要任何占位标记。

**compact 设计（21 B 小帧 → 33 B/条）**

- 载荷存**原始字节**而不是 hex：小帧体积直接减半；`session.history` 等 IPC 仍输出 hex（读取层转换）。
- **origin 字典在槽里**（`origins` 数组），记录里只存 1 字节 id；首次出现新来源时写一次快照。
- 字典满（§2.3 两条上限）后新来源用 `originId=255` 内联，常见场景不会触发。
- 时间戳用完整 u64。**注意**：增量编码可再省 4 B/帧，但会让崩溃后的记录区扫描失去时间锚点，
  且时间锚点必须依赖头部（头部丢了就没时间），收益（约 4 B/条）不值这个代价，留待 v3 再评估。
- **记录区不做逐条 CRC**：包格式自带长度字段、尾部半包按规则截断；逐条加 4 B 会让 33 B/条
  变成 37 B（+12%）。代价是位翻转会表现为"数据错"而不是"读到报错"——串口调试场景可接受，
  需要更强校验时见 §14 待定项。

### 2.7 写入策略（批量 + 零 fsync + 尾页重写）

```
缓冲 = batch_kb（默认 8 KB，范围 4~64，必须是 4 KB 的倍数）
  缓冲满          → 一次 write()（整段一次系统调用，不拆多段）
  距"本批第一个未刷字节到达"≥ flush_max_ms（默认 1000；范围 0..600000）→ write()
       ↑ 计时锚点是"第一个未刷字节"，不是"上次 flush"
  显式 flush：关闭、停录、推送移交、导出与搜索前、崩溃恢复后
  fsync：默认只在 关闭 / 停录 / 推送移交 三个点；
         [storage] fsync=true 时才每次 flush 后 fsync（SSD 上代价高，默认关）
```

**为什么这么定（写放大的真实来源）**

1. **每次 `write()` 都会让 NTFS 更新文件长度/时间戳并写 `$LogFile`**，代价与调用次数相关、
   与字节数关系不大。所以压调用次数比压字节数更值钱。
2. **页内重写（RMW）**：不到 4 KB 的追加会反复重写同一个 4 KB 页。低速率设备（200 B/s Modbus 轮询）时：

| `flush_max_ms` | 每次写 | 同一页被写回 | 物理放大 |
|---|---|---|---|
| 200 | ~40 B | ≈25 次 | **≈25×**（4 KB/s 换 200 B/s） |
| 1000（默认） | ~200 B | ≈5 次 | ≈5× |
| 5000 | ~1 KB | ≈4 次 | ≈4× |
| 0（关定时器） | batch_kb | 1 次 | **1×**，窗口 = `batch_kb/速率`（默认 8 KB ≈ 41 s @200 B/s） |

（回写间隔取量级：Windows 脏页回写数秒级，Linux `dirty_writeback` 默认 5 s / `dirty_expire` 30 s。
上表只用来说明量级，不精确到毫秒。默认取 1000 是"≤1 s 可见"与"≈5× 放大"的折中；
纯长时间泡机、可接受长窗口的场合建议设 0。）

**定时器的闸门（v1.3.1 补）**：缓冲满优先，定时器只在"速率 < `batch_kb / flush_max_ms`"时才有机会触发，
即 `有效间隔 = min(flush_max_ms, batch_kb / 速率)`。所以**调大间隔只对低速链路有收益**：

| `flush_max_ms` | 定时器能生效的最高速率（`batch_kb=8`） | 200 B/s 时的物理写入 | 数据可见延迟 |
|---|---|---|---|
| 1000（默认） | 8 KB/s | ≈800 B/s ≈ 69 MB/天 | ≤1 s |
| 10000 | 819 B/s | ≈400 B/s ≈ 34 MB/天 | ≤10 s |
| 30000 | 273 B/s | ≈273 B/s ≈ 23 MB/天 | ≤30 s |
| 60000 | 137 B/s | 8 KB/41 s = 200 B/s ≈ 17 MB/天 | 41 s（缓冲先满，定时器已失效） |
| 600000 | 13.6 B/s | 与 60000 完全相同 | 同上 |
| 0（关定时器） | — | 8 KB/41 s = 200 B/s ≈ 17 MB/天 | 页满（200 B/s 时 41 s） |

- **对 200 B/s，30 s 是最后一个有意义的档**；再大就等于关掉定时器（缓冲 41 s 先满）。
- 10–20 分钟只在**极慢**链路（< 14 B/s）上有意义；工业软件敢用那个量级是因为"整文件重写 + UI 卡顿"，
  我们一次 flush 只是追加 ≤8 KB，亚毫秒，成本结构不同。
- 反向代价：崩溃窗口的**字节**上界永远是 `batch_kb`（8 KB），但**时间**窗口 = 间隔；
  调试场景最值钱的是"崩溃前那几秒"，所以默认值保持 1000，不跟着"省盘"走。
- 空闲不写：缓冲为空时定时器不触发，闲着的会话不会产生周期性写入。

3. **页对齐在什么条件下成立**（v1.3.1 修正措辞）：

   - **满页写必然对齐**：记录区起点 0x2000 是 4 KB 对齐 + `batch_kb` 是 4 KB 倍数 + 每次整段写；
   - **`flush_max_ms` 触发的小写会破对齐**：缓冲区没满就写，会在页中间落笔，这正是上表
     `≈5×` 的来源。这是为了"≤1 s 可见"主动付的代价，不是 bug；
   - **关闭时那次不满页的 flush 同样会破对齐**，把文件尾留在一个页的中间；
   - 关闭留下的尾巴由下面的"尾页重写"在**下一次接续**时一次抹平；
     会话进行中的小写由 `flush_max_ms` 的取值调节，尾页重写管不到它（也不该管）。

4. **尾页重写（取代 v1.2 的填充记录）**

```
end        = 最后一条完整记录的结束偏移（扫描得出）
tailStart  = (end > 0x2000) ? ((end - 1) & ~0xFFF) : 0x2000   // 记录所在页的页起点
free       = tailStart + 4096 - end                            // 0 = 该页已满，无需重写
```

触发条件：重开后**第一次 flush** 且 `free > 0` 且缓冲区非空。执行：

```
take   = min(free, len(buf))
prefix = 磁盘上 [tailStart, end) 的字节        ← 必须重读，禁止用内存副本
merged = prefix + buf[:take] + 补零到 4096
pwrite(merged, tailStart)                      // 恰好一次 4096 B 写
buf    = buf[take:]                            // 剩余数据留在缓冲，下一批从 tailStart+4096 起
```

- **切分是硬规则**：一页只写一页的量。`buf` 比 `free` 大时，多出来的部分**不进这一页**，
  留在缓冲里等下一次 flush；写完之后下一个写入地址就是 `tailStart+4096`，天然对齐。
- **`take == len(buf)` 时**：页被"前缀 + 全部新数据 + 补零"填满，缓冲清空，后续同样从页边界开始。
- **前缀必须从磁盘重读**（v1.3.1 新增硬约束）：上一次会话关闭时的内存缓冲里可能还有
  "以为写了、其实没落盘"的字节，用它当前缀等于把脏数据写回已提交区域。读到的 `[tailStart, end)`
  也是扫描时用来确定 `end` 的同一份字节。
- **已提交前缀必须逐字节原样拼接**（禁止解析再序列化）。这样撕裂写只会影响"新旧不同的那一段"
  = 刚追加的区域，已提交记录被写成相同字节，不会丢。
- **失败即停录**：重写返回 I/O 错误时按"记录写失败"处理——停录 + 事件，**不允许静默退回
  "从 end 继续普通追加"**。退回会让页内出现非对齐尾巴，还会把一次真实的 I/O 故障藏起来。
- **写前必须做限额检查**：重写会把 EOF 推到页尾（最多 +4096 B），所以先看
  `tailStart + 4096` 是否越过 `max_size_mb`、写完后卷可用空间是否跌破 `min_free_mb`；
  任一越界 → **不写这一页**，停录告警，文件保持可读可导出，下次重开再试。
- **空会话零写**：重开后没有新数据就一次都不写（填充记录方案是"开了就写"）。
- **不累积空洞**：反复开关同一文件不会像填充记录那样每次多占 ≤4 KB。
- **不得推广成"每次 flush 都重写尾页"**：那会把顺序追加变成同页反复读改写，正是上表第 2 条要躲的 25×。
  批量缓冲仍然是"攒满一页再写"；尾页重写只在"跨会话接续点"发生一次。
- **坏尾判定**：若 `EOF > tailStart + 4096`（垃圾跨了一整页以上），先 `SetEndOfFile(end)` + fsync
  再继续；垃圾落在尾页之内则不用截断，整页重写会把它抹成零（§2.9）。

| 尾页状态 | v1.2 填充记录 | v1.3.1 尾页重写 |
|---|---|---|
| 重开时的写 | 约 R 字节零 + 11 B 头（R = 4096 − P） | 读 4 KB + 写 4 KB，且**只在有数据时** |
| 新数据 D < R 的总写 | R + 4096 | **4096** |
| 反复开关累积 | **每开一次 +4 KB 空洞** | **0** |
| 空会话（开了不录） | 写 R 字节 | **0** |
| 坏尾修复 | 截断 + 填充写 | 一次整页写（尾页内）/ 截断（跨页） |

（P = 尾页已用字节，R = 4096 − P。数字按"每页 4 KB、每次只处理一页"计。）

5. **显式不做**：
   - 预分配（`SetEndOfFile`/`fallocate` 预留 512 MB 等于立刻写 512 MB 零）；
   - `mmap` 写入（脏页回写时机不可控，写放大不可控）；
   - 写到压缩卷 / EFS / 网络盘（检测到则告警；写模式默认拒绝，见 §3）。
6. **稳态代价**：零 fsync、满页写对齐、一次系统调用。
   115200 合包后约 12.3 KB/s → `batch_kb=8` 时约 **1.5 次写/秒**。

**其余约定**

- **槽可变、记录区除最后一页外只追加**：设置通过整页覆盖槽更新；记录区顺序追加，
  唯一的例外是 §2.7 第 4 条的尾页重写。
- **尾部半包**：读时跳过；写模式打开时按 §2.9 处理（尾页内覆盖 / 跨页截断）。
- **不轮转**：超过 `max_size_mb` 停止记录并告警（保持"一个标签一个文件"的身份），由用户决定
  新建会话或调大上限。
- **可读性**：raw 载荷无法直接 `grep`；人读场景走导出（log/txt/csv），旧 `history/*.log` 仍是 hex。

### 2.8 索引：无 sidecar

打开时顺序扫描记录区，在内存里建索引——每 512 条记一个锚点 `{offset, ts, n}`，
索引只服务时间定位与分页，**不落盘**。

- 扫描成本：512 MB ≈ 0.5 s、4 GB ≈ 4 s（SSD 冷缓存，顺序读）；
- 每次打开都重建，因此**不存在"索引损坏/缺失"这种状态**；
- 关闭/崩溃都不需要维护索引，少一整类故障；
- 若以后实测"超大文件打开太慢"，再引入**可选**的文件内检查点记录（不是 sidecar）。

### 2.9 打开与关闭流程

```
写模式打开（openAppend）：
1. 读两槽头（各 32 B）→ 按 §2.4 选槽 → 解析 payload 得到设置
2. 两槽都无效 → 拒绝打开（记录区仍可"救回导出"，见 §10）
3. 扫描记录区 → 得到最后一条完整记录的结束偏移 end，按 §2.7 第 4 条算出 tailStart 与 free
4. 若 EOF > tailStart + 4096（垃圾跨页）→ 截断到 end（SetEndOfFile + fsync），记日志；
   尾页之内的坏尾不处理：首次 flush 的整页重写会把它抹成零
5. free > 0 时记下"待重写尾页"，等待首次 flush；free == 0 则直接从 end 追加
6. 若 record 状态与用户意图不符（例如「由文件开始」要续录）→ 写一次快照（§2.5 去重后可能不写）
7. 返回设置 + entryCount（来自扫描）

只读打开（openRead）：
1. 同上 1–3；不写任何字节
2. 尾页半条只做"截断位置"标记，供分页用
```

**没有 `clean` 位**（v1.2 删除，之后沿用）：它的信息量只有"上次是否正常关闭"，而这件事
打开时扫一遍尾部就能知道（尾部有半条 = 上次不正常）。删掉它省掉"打开写一次、关闭写一次"的
两页写入，也少一个可能与现实不符的状态位。

```
关闭（停录 / 关闭标签 / 推送移交）：
1. flush（不满一页就写不满一页，不补零——补零留到下次跨会话时由尾页重写完成）
2. fsync
3. 写一次快照（record=false，带 stats；内容没变则 §2.5 去重跳过）
4. 关闭句柄
```

**新建文件**：一次 write 写满 8 KB 头（槽 A 有效、seq=1，槽 B 全 0），再开始追加记录。
不要只写槽 A 就停——那会让 0x1000–0x2000 变成空洞，虽然读出来是 0，但文件布局不干净、
也少了一处"槽 B 是可写目标"的显式初始状态。

### 2.10 容量与上限

- 偏移 u64 → 理论 16 EB；单条记录 ≤ 16 KB。
- 固定开销：头部 **8 KB** / 文件（两槽），无 sidecar；尾页重写不再累积额外空间。
- 文件系统：NTFS/exFAT 不受限；**FAT32 单文件 4 GB − 1 字节**，`sessions/` 在 FAT32 上时
  硬上限 4 GB 并提前告警。
- 默认软上限 `max_size_mb = 512`（达到即停录告警），建议硬上限 4096 MB。
- 增长速率：**合包后 ≈1.01–1.07×**，逐帧成条（最坏）≈1.57×（= 33 B / 21 B）。

| 波特率 | 原始速率 | 合包后（16 ms 窗口） | 逐帧（最坏） | 512 MB 可录（合包 / 逐帧） | 4 GB 可录（合包 / 逐帧） |
|---|---|---|---|---|---|
| 115200 | 11.5 KB/s | ≈12.3 KB/s（1.07×） | ≈18.1 KB/s（1.57×） | 12.2 h / 8.2 h | 97 h / 66 h |
| 230400 | 23.0 KB/s | ≈23.8 KB/s（1.03×） | ≈36.2 KB/s（1.57×） | 6.3 h / 4.1 h | 50 h / 33 h |
| 921600 | 92.2 KB/s | ≈92.9 KB/s（1.01×） | ≈144.8 KB/s（1.57×） | 1.6 h / 1.0 h | 12.8 h / 8.2 h |

（合包窗口取守护进程现有行为量级；若实际窗口不同，两张口径按比例换算即可。）

## 3. 锁与独占（写者互斥、读者共存）

### 3.1 规则

**问题背景**：`CreateFileW(share=0)`（连读都不许）会把杀毒扫描、备份、系统搜索索引全部挡在门外，
部分安全产品会拦截或反复重试，把"安全设计"变成"兼容性故障"。

```
Windows
  写者：CreateFileW(GENERIC_READ|GENERIC_WRITE, dwShareMode = FILE_SHARE_READ)
  读者：CreateFileW(GENERIC_READ,               dwShareMode = FILE_SHARE_READ|FILE_SHARE_WRITE)
Unix
  写者：O_RDWR|O_CREATE + flock(LOCK_EX|LOCK_NB)
  读者：O_RDONLY        + 不加锁
```

**为什么 Unix 读者不能加 `LOCK_SH`**：`flock` 的 `LOCK_SH` 与写者的 `LOCK_EX` **互斥**，
加锁等于"只要有人在写，读者就打不开"，与 Windows 的 `FILE_SHARE_READ` 语义正好相反。
读者不加锁后，两侧语义才一致：**写者互斥、读者自由**。

| | Windows | Unix |
|---|---|---|
| 写者 | `share = FILE_SHARE_READ` | `flock(LOCK_EX\|LOCK_NB)` |
| 读者 | `share = READ\|WRITE` | 不加锁，`O_RDONLY` |
| 写-写 | 第二个写请求被内核拒（share 不含 WRITE） | 第二个 `LOCK_EX` 失败（`EWOULDBLOCK`） |
| 写-读 | 允许 | 允许 |
| 强制性 | **强制**（内核对 share 把关） | **advisory**（只拦守规矩的进程） |

- 读者不加锁的代价：Unix 上任何无视 `flock` 直接 `O_RDWR` 的程序都能写进来，我们拦不住。
  这是 `flock` 的固有局限，写进文档、不假装能防。
- `flock` 与 `fcntl` 锁**互相看不见**：第三方用 `fcntl` 加锁我们检测不到。
- **第三方短暂持锁**（例如备份工具用 `LOCK_SH` 扫一遍）会让写者打开失败：复用推送交接那条
  "3 × 200 ms 重试"，不新增机制。
- 网络盘（UNC）与压缩/EFS 卷：写模式默认拒绝（`[storage] allow_network_dir=true` 可强行放行），
  读模式允许。理由：SMB/NFS 的共享语义、`fsync` 语义、`flock` 可靠性都不能保证 §2.4/§2.7 的不变量。
- **同一进程**：内存表记录已打开路径，重复写打开直接拒绝（读打开允许）。
- **错误**：`errFileLocked{path, mode, holderHint}`；GUI 文案"文件已被占用（GUI / 守护进程 / 其他程序）"。

### 3.2 写者探测（`history.files` 的 `locked` 字段）

读者不加锁之后，"文件是否被占用"不能再靠"打开失败"判断，必须显式探测**写者**：

```
Windows：CreateFileW(path, GENERIC_WRITE, dwShareMode = 0)
           成功 → CloseHandle，locked = false
           ERROR_SHARING_VIOLATION → locked = true
Unix   ：open(path, O_RDWR)
           flock(fd, LOCK_EX|LOCK_NB)
             成功 → flock(fd, LOCK_UN) + close，locked = false
             EWOULDBLOCK → locked = true
```

- `locked` 的语义是**"存在写者"**，不表示读者数量（读者本来就不加锁，数不清也不需要数）。
- 这是**瞬时探测，不持有锁**：探测成功后立刻释放，写者可能在探测与真正打开之间抢到锁——
  以真正 `open` 的结果为准，探测结果只用于列表展示。
- 探测会与写者短暂竞争：Unix 侧写者的 `LOCK_EX` 可能因为探测的几微秒而失败，
  靠"3 × 200 ms 重试"吸收；Windows 侧 `share=0` 的探测窗口同理。窗口极小但不为零，写进风险。
- Windows 侧还有一个误判方向：若第三方**以 `share=READ`（拒绝写）打开**了该文件，我们的
  `GENERIC_WRITE` 探测会失败，把读者误报成写者。这个方向保守（只是多显示一个"被占用"），可接受。
- 探测失败**不得**返回错误给 GUI，只把 `locked` 置 true。

## 4. 守护进程会话模型

- 现有 `Process`（live）增加 `record bool` 与 `fileWriter`（写句柄）。**句柄只在单一写协程内使用**。
- 新增 **写协程**（每个录制会话一个）：从 channel 收 `{records, settings, flush, close}`，负责：
  1. 按 §2.7 合并刷记录缓冲（含跨会话的尾页重写）；
  2. 把设置快照合并到 ≤1 次/秒落盘（只写最终状态 + 内容去重，§2.5）；
  3. 处理写错误（失败 → 停录 + 事件）。
- **背压（v1.3.1 新增）**：channel 是**有界字节队列**（默认 8 MB）。串口 RX 协程写入时阻塞等待，
  **绝不丢数据**（串口数据不可重现，丢一条就是永久缺数据）。等待超过 1 s 仍满 → 视为
  "写盘跟不上"：停录 + 事件 + 状态栏告警，队列里已有的数据继续写完再关句柄。
- 新增 `ReplaySession`：`id = "file-<uuid8>"`、`path`、读句柄、槽设置、内存索引（§2.8）、分页游标。
- 统一历史来源接口 `historySource`：
  - `ringSource`：live 会话，读 5 MB 共享内存环（现有逻辑）。
  - `fileSource`：replay 会话，按内存索引直接分页（不建环、不占 5 MB）。
- `process.list` 合并两类，条目带 `kind`（`live`/`replay`）、`sessionFile`、`record`、`created`、`entryCount`；
  replay 条目 `status="replay"`、无 `connected`。
- `fileIndex[path]` → sessionId：同一文件只允许一个会话，重复 `history.open` 返回既有 `sessionId`（`reused=true`）。

`firstPage` 是第一页数据（结构同 `session.history` 的返回），打开时一次带回，省一次往返。
旧字段名 `entries` 不再使用（重名歧义：数量还是数据）。

**`keyword` 的语义**：只匹配槽内的 `label` / `notes` / `port`（子串、大小写不敏感），
**不扫记录内容**——扫内容要读整份文件，那是 `SearchHistory` 的活。不匹配的文件不出现在结果里；
`offset`/`limit` 仍对结果集分页。

**分页游标的语义（v1.3.1 明确）**

- 游标本体是**记录序号**（从 0 起的第 N 条），不是时间：这样即使文件头丢了、时间戳乱了，翻页也不会错位。
- `beforeMs` / `sameTsSkip` 是"时间 → 序号"的**定位提示**：正常文件用内存索引二分到 `beforeMs` 附近，
  再用 `sameTsSkip` 跳过同毫秒的重复项。
- 扫描发现 `ts` 倒退时（§2.6），该文件在 `header.tsTrusted = false`；此时忽略二分，从记录 0 线性扫描，
  结果仍正确、只是慢；GUI 据此在状态栏标注"时间戳异常"。
- `header.tsTrusted` 是文件级属性，放在 `history.open` / `OpenLocalFile` 的 `header` 里，分页响应不重复。

**参数上限**

| 参数 | 约束 |
|---|---|
| `limit` | 1..2000（默认 200） |
| `offset` | ≥ 0 且 ≤ `entryCount`（另加 1e8 上限防误传）；超出即空结果 |
| `keyword` | ≤ 256 字符；按 UTF-8 字节截断，不做正则解释 |
| `fromMs/toMs` | 0 .. 当前时间 + 1 天；`fromMs > toMs` 视为空结果 |
| `out`（导出路径） | 必须是绝对路径、父目录存在、扩展名 ∈ {log,txt,csv}；已存在需 `overwrite=true` |
| `file`（打开路径） | 绝对路径，`Clean` 后比较；`mode=attach` 时文件必须已存在 |

`history.files` 的设置按 `(path, size, mtime)` 缓存，避免每次列目录都重读全部槽头。

**`session.settings` 的热更新范围**

| 键 | 可热更新 | 生效方式 |
|---|---|---|
| `record` | 是 | 立即停/开记录（写一次快照） |
| `label` / `notes` | 是 | 立即（写一次快照） |
| `encoding` | 是 | 影响后续 TX 编码与导出默认值 |
| `port` / `baud` / `dataBits` / `stopBits` / `parity` / `flow` / `mode` / `portB` / `baudB` | 否 | 返回 `requiresReconnect=true`，由 GUI 走重连流程 |

失败时返回 `{ok:false, error:{code:{locked|invalid|io}, message}}`，不做半应用：先校验全部键，
再一次性应用。

**导出格式定义**

```
log ：每行 "[time] dir origin  hex"（与旧 history/*.log 的观感一致，便于老用户）
txt ：按 encoding 解码后的文本行，非打印字符转义；仅数据方向，system 行以 "[sys] " 前缀
csv ：表头 index,time,direction,origin,length,hex,text
      index      1 起连续序号，按文件顺序
      time       RFC3339 带时区（默认本地时区，--utc 可切），毫秒精度
      direction  rx | tx | sys | p1 | p2
      origin     名称；查不到字典则为 unknown(id=N)
      length     payload 字节数（不含 12 B 记录头）
      hex        大写连续十六进制，无前缀无分隔；空载荷留空
      text       按 encoding 解码，仅人读；含逗号/引号/换行时按 RFC 4180 加引号
      防注入    任何以 = + - @ 开头的单元格前置单引号
```

**事件**

- 新增 `sessions-changed`，payload `{kind:"live"|"replay", sessionId, action:"open"|"close"|"update"}`。
- `process-changed` 增加 `kind` 字段（增量字段，旧前端忽略即兼容）。
- 旧前端不认识 `sessions-changed` 时，唯一表现是"CLI 打开的 replay 不自动出标签"，不影响功能。

## 8. 状态机与锁交接

```
无文件 ──开启记录──▶ recording(live) ──关闭记录/断开──▶ closed(clean|unclean)
   ▲                        │                                  │
   │                        └──── 崩溃/断电 ────────────────────┘
   │                                                           │
   └──── 新建会话（单端口/转发）        closed ──history.open──▶ replay ──push/attach──▶ recording
```

**两条交接路径（v1.3.1 区分）**

| 路径 | 谁持有 | 需要做什么 |
|---|---|---|
| A. 本地只读标签 → 守护进程 | GUI 只持**读**句柄 | close 读句柄 + 请求 `history.open`。**没有 flush/fsync**——只读没有脏数据 |
| B. 守护进程内部关闭 / 移交 | 守护进程持**写**句柄 | flush → fsync → 写快照（内容有变才写）→ close |

（v1.3 把这两条混成一句"GUI 先 close+释放，再请求守护进程 open"，对只读标签是多余动作；
A 路径的 `flush+fsync` 在 v1.3.1 删掉。）

```
A 路径时序：
local-readonly ──close 读句柄──▶ history.open
   成功 → daemon-held / replay（之后 GUI 一律走 IPC）
   失败 → 查 history.files：
            file.locked 为真且被守护进程持有 → 直接开 replay 标签（不重复抢锁）
            否则重试 3 × 200 ms
              仍失败 → 重新获取本地读句柄，标签留在本地只读，提示"被其他程序占用"
```

- 交接窗口里第三方抢占只可能发生在 `close` 与 `open` 之间，重试 + 查询足以收敛；
  不做 `.lock` 占位文件（崩溃残留的代价比这个窗口大）。
- 记录开关：开 → 无文件则建（一次写满 8 KB 头：槽 A 有效、槽 B 全 0），有文件则按 §2.7 第 4 条
  重写尾页后追加；关 → flush + fsync + 写一次快照（record=false，内容有变才写）+ 关闭、保留文件。

## 9. 设置项

`settings/gui.ini`：

```ini
[file]
drop_action = local     ; local | push
recent_dir =
```

`settings/daemon.ini`：

```ini
[storage]
dir = sessions          ; 相对 exe 目录
record_default = false
max_size_mb = 512       ; 达到即停录告警
min_free_mb = 256       ; 卷可用空间低于此值即停录（写前检查）
keep_days = 30          ; 保留天数；0 = 不清理
batch_kb = 8            ; 记录写缓冲，4~64，必须是 4 KB 的倍数
flush_max_ms = 1000     ; 刷盘上界 0..600000；0 = 关掉定时器，只在满页/显式动作时写
                        ; 计时锚点是"第一个未刷字节到达"，不是上次 flush
                        ; 预设：即时 1000 / 平衡 10000 / 省盘 0
                        ; 有效间隔 = min(flush_max_ms, batch_kb / 速率)，见 §2.7
fsync = false           ; 每次 flush 后 fsync；默认只在关闭/停录/移交时 fsync
allow_network_dir = false
```

（头部固定 8 KB，没有 `header_kb`。）

**`keep_days` 清理策略（v1.3.1 明确）**

- **只在守护进程启动时执行一次**，不是定时任务（避免跑机时周期性删文件）。
- 只删同时满足三个条件的 `.stlog`：槽能正常解析、`locked == false`（无写者）、
  `created`（取不到则用 mtime）早于 `keep_days` 天。
- 槽解析失败的文件**不删**（可能是重要数据，只是头坏了），只记一条日志提醒人工处理；
  这也意味着损坏文件会永久堆积——写进风险。
- 每次删除记日志：路径、大小、created。
- Windows 上文件被读者占用时删除会被拒（`ERROR_SHARING_VIOLATION`）→ 跳过、不报错；
  Unix 上删除成功后已打开的读者仍能读完（fd 持有 inode）。
- 只动 `sessions/` 下的 `.stlog`，**不碰** legacy `history/*.log`、不碰导出目录。

会话设置（推送后由守护进程持有）：端口参数、single/forward、转发端口、记录开关、导出默认格式。

## 10. 错误与边界

| 场景 | 行为 |
|---|---|
| 文件被其他写者占用 | `file_locked`，提示"文件已被占用（GUI / 守护进程 / 其他程序）" |
| 文件被守护进程占用，GUI 拖入 | 若 `drop_action=push` 或点推送 → 复用已有会话；否则提示"已被守护进程接管" |
| 魔数不对 / 不是本格式 | 尝试 legacy 只读路径，失败则报错 |
| 单槽损坏（CRC / endMagic / len 越界 / JSON 坏） | 该槽作废，用另一槽；**不修复、不覆盖**损坏槽（留着做回退依据） |
| `slotVersion` ≠ 1 / `payloadVersion` > 2 | 该槽无效；两槽都如此 → 提示"由更新版本创建" |
| 两槽都坏 | 拒绝打开（设置不可信）；**记录区仍可从 0x2000 扫描做"救回导出"**，origin 一律显示 `unknown(id=N)` |
| 快照序列化后 > 4000 B | 冻结 origins 字典、新来源改内联；仍超则拒绝写入并报错（属 bug，不是用户错误） |
| 快照内容与当前槽逐字节相同 | 跳过写入（§2.5 去重），不算错误 |
| 尾页未满（正常关闭后的常态） | 不是错误；下次写入时整页重写补齐（§2.7 第 4 条） |
| 尾页内有半条记录 | 不截断；整页重写时组装成"最后一条完整记录 + 新记录 + 补零" |
| 坏尾超出尾页（`EOF > tailStart + 4096`） | 截断到 `end`（SetEndOfFile + fsync），记日志 |
| **尾页重写失败（I/O 错误）** | **停录 + 事件**；不退回普通追加（会破坏对齐纪律并掩盖故障） |
| **尾页重写将越过 `max_size_mb`** | 不写这一页，停录告警；文件保持可读可导出 |
| **尾页重写将使可用空间跌破 `min_free_mb`** | 同上 |
| 记录引用的 `originId` 不在槽字典里 | 显示 `unknown(id=N)`，**不当坏记录**，继续读 |
| 记录区中间出现坏记录（`dir`/`len`/`originId=0` 越界） | 读到该处即停（不猜、不跳），已读部分正常展示 |
| 磁盘满（`ENOSPC`/`DISK_FULL`） | 停录、flush 能写的部分、发事件、状态栏告警；文件保持可读可导出 |
| 可用空间 < `min_free_mb` | **写前**检查（每 64 MB 或每 30 s 一次），提前停录并告警 |
| 达到 `max_size_mb` | 在**下一批写入前**停录并告警，不写出超限的那一页 |
| 写入返回 I/O 错误（EIO 等） | 停录、关闭句柄、会话保留但标 `record=false`，事件提示"写盘失败" |
| 写协程队列满超过 1 s | 停录 + 事件（不丢队列里已有的数据，之后的数据不再进队列） |
| 推送失败（第三方抢占 / 守护进程拒绝） | GUI 重试 3×200 ms → 重新获取读句柄、标签留在本地只读、提示原因 |
| 导出目标已存在且未给 `overwrite` | 拒绝，返回 `exists`，不动原文件 |
| 导出失败（写入中途 / rename 失败） | 删除 tmp，保留原文件；返回错误。**tmp 必须与目标同目录**（跨卷 rename 必失败） |
| 超大文件 | 按页读 + 内存索引定位，不整文件进内存；扫描耗时见 §2.8 |
| 网络盘 / 压缩卷 / EFS | 写模式拒绝（可配放行），读模式允许 |

## 11. 兼容与迁移

- 老 `history/*.log`：hex 载荷、无 `SLOG` 头 → 走 legacy 只读路径，可离线打开、可 replay、可导出；
  不可作为 live 追加目标。
- 新 `.stlog`：raw 载荷 + origin 字典；IPC 输出仍统一 hex（读取层转换），前端与 CLI 看到的 JSON 形状不变
  （除 `entries` → `entryCount` 的改名）。
- `history.attach`（现有）保留，行为等价于「由文件开始」的 replay 分支。
- 不自动转换历史文件；需要时用 `export` 转 csv/txt 再迁。
- 格式版本策略：`slotVersion=1` 固定布局（记录起点 0x2000）；`payloadVersion` 只加字段不轻改语义；
  未来若布局要变，升 `slotVersion` 并拒绝旧程序写入。

## 12. 测试计划

**槽与恢复**

- 槽校验逐项：magic / `slotVersion=2` / `flags≠0` / `len>4000` / `0x20+len+8>4096` / crc 错 /
  endMagic 错 / JSON 坏 / `payloadVersion=3` → 该槽无效；
- 选槽：两有效取 seq 大；seq 等取 ts 大；再等取 A；一有效用它；都无效拒绝；
- **torn write**：把槽截断到 0..4095 的抽样长度（如 0/1/32/33/34/2048/4095），
  写模式必须回退另一槽且设置完整；
- **写乱序**：先写 seq 11 到 B、再补写 seq 10 到 A（模拟回写乱序），选中结果必须是 seq 11 且状态正确；
- 写槽：target 必须是 seq 较小者（无效槽优先）；`newSeq = max+1`；断言每次写入恰好 4096 B；
- **去重**：第二次序列化结果与生效槽相同时不得产生任何写入（`write` 计数为 0）、seq 不变；
- 快照预算：origins 追加到第 255 条（硬上限）或超 4000 B（字节预算）→ 冻结字典、新来源内联、
  旧记录仍可解；同名字符串不重复占号；单个元素 > 64 B 被拒；
- 无 `clean` 位：只读打开不写任何字节；写模式打开只在状态变化时写；关闭写 0 或 1 次（去重后）；
- **空会话零写**：打开→不产生记录→关闭，且状态无变化 → `write` 调用次数为 0（依赖 §2.5 去重）；
- 记录区起点：两槽全坏时仍能从 0x2000 扫出记录并导出，origin 显示 `unknown(id=N)`。

**尾页重写**

- **切分**：`buf` 大于 `free` 时只写 `free` 字节进尾页、其余留在缓冲、下一次从 `tailStart+4096` 起；
  `buf` 小于 `free` 时整页补零、缓冲清空；
- **前缀字节一致**：重写前后取 `[tailStart, end)` 逐字节比对，必须完全相同；
- **前缀来自磁盘**：先把磁盘上前缀改成"错误副本"再触发重写，验证程序读的是磁盘内容而不是内存缓冲
  （用可注入的 reader 断言读取范围恰好是 `[tailStart, end)`）；
- **重写撕裂**：把重写页按 0/512/1024/2048/4095 截断模拟，已提交记录必须全部可读、`end` 不变；
- **失败即停录**：注入 EIO 到重写写调用 → 会话进入停录、事件发出、**不产生任何普通追加**；
- **限额**：把 `max_size_mb` 设为 `tailStart+4096` 之下 → 重写被拒、停录、文件仍可读；
  `min_free_mb` 同理；
- **反复开关不增长**：开-关 100 次（无新数据）→ 文件大小不变、`write` 为 0、mtime 不变；
- **坏尾两类**：尾页内半条（不截断、靠重写覆盖）与超出尾页的垃圾（截断到 `end`）分别验证；
- **禁止推广**：注入断言——连续两次 flush 之间，同一页最多被写一次（防止有人把尾页重写搬到每批 flush）。

**记录与批写**

- 解析：raw 载荷、system 文本、半包、坏包、`len > 16384`、`dir ∉ 0..4`、`originId=0`、
  `originId=255` 且内联超 64 B、`originId∈1..254` 但字典缺失（→ `unknown(id=N)`，继续读）；
- 时间戳：写入侧单调钳制（注入回拨时钟）；读取侧不因 ts 倒退判定损坏，但必须置
  `header.tsTrusted=false`，且分页结果与正常文件一致（走线性定位路径）；
- 批写：缓冲满触发一次 write（断言调用次数）；`flush_max_ms` 用可注入时钟；显式 flush 点；
  崩溃丢 ≤ `batch_kb`；`fsync=false` 时稳态 fsync 次数为 0（关闭/停录/移交除外）；
- **定时器锚点**：缓冲为空、且距上次 flush 已远超 `flush_max_ms` 时到达 1 条记录，
  **不得立即 flush**（计时必须从"第一个未刷字节到达"起算）；随后在 `flush_max_ms` 边界处写一次；
- **闸门**：把速率压到 `batch_kb/flush_max_ms` 以下，定时器才触发；高于阈值时只由缓冲满触发，
  调 `flush_max_ms` 不改变写入次数。

**锁与探测**

- 写-写互斥（两进程，第二个必须失败）；
- **写-读并发**：Unix 上读者不加锁，必须能在写者持有 `LOCK_EX` 时打开并读到已刷数据；
  Windows 上读者用 `share=READ|WRITE` 打开，同样必须成功；
- 读-读并发；同一进程重复写打开被拒；
- **探测**：写者持锁时 `history.files` 的 `locked=true`；无写者时 `false`；探测后不得残留锁
  （随后另一个写者必须能打开）；
- 第三方持 `LOCK_SH` 时写者打开失败 → 重试 3×200 ms 的路径可恢复。

**磁盘与故障**

- 模拟 `ENOSPC`：停录 + 事件 + 文件仍可读可导出；可用空间低于 `min_free_mb` 时提前停录；
- 槽写失败（注入 EIO）：旧槽继续生效、记录不中断、事件可见；
- **背压**：把队列压到满 → 生产者阻塞；超过 1 s → 停录 + 事件，且队列中已有数据全部写完；
- 只读卷 / 无权限目录：建文件失败的错误信息可读、不崩；
- `keep_days`：构造 3 个文件（正常 / 槽坏 / 被写者占用）→ 只删第一个；日志有记录。

**安全**

- 恶意文件（巨型 `len`、`seq` 全 1、坏 JSON、超长 label、`origins` 上千条、保留名/路径穿越文件名）
  → 不崩、不越界、不无限循环；
- CSV 导出：`= + - @` 开头加前缀、引号/逗号/换行按 RFC 4180 转义、`unknown(id=N)` 正确落格；
- 导出走 tmp + rename，失败删 tmp 且保留原文件；目标已存在且未给 `overwrite` 时拒绝。

**集成**

- 守护进程建会话 → 开记录 → 写 → 关 → 重开续写；`history.open` replay 分页（`firstPage` + `entryCount`）；
- 推送（GUI 关读句柄 → 守护进程获取），含"交接窗口被第三方抢占"的失败路径；
- CLI/MCP 检索打开；GUI 拖入离线只读 + 导出；槽里的端口参数预填「由文件开始」；同一文件二次写打开被拒；
- `session.settings` 热更新：`record`/`label`/`notes`/`encoding` 立即生效，`port` 等返回 `requiresReconnect`。

**性能**

- 230400 合包后 ~60 包/s 连跑 1 小时：**216,000 条 = 60 × 3600**；每条记录 396 B
  （384 B 载荷 + 12 B 记录头），合计 **85.5 MB / 81.6 MiB**。统计 `write()` 次数
  （目标 ≤ 1.5 次/s @ `batch_kb=8`）、fsync 次数（稳态 0）、CPU 与 UI 延迟；
- 元数据写：一次会话应 ≤ 4 页（16 KB），并断言没有定时写；
- 1 GB 文件打开扫描耗时（目标 ≤ 1 s 热缓存）与分页、流式导出；
- `batch_kb=4/8/16` × `flush_max_ms=0/200/1000/5000` 组合对比：记录写调用次数与进程 I/O 计数。

## 14. 风险与待定

1. **`process.list` 混入 replay** 对现有 `syncDaemonSessions` 的改造量（GUI 目前把所有进程当会话标签处理）。
2. **并发读的期望管理**：读者可能读到"半个包"，前端必须表现为"实时追加中"而不是数据错误；
   需要 UI 文案与刷新节奏（500 ms）约定。
3. **元数据写固定 4 KB**：短会话（100 条 ≈3 KB 数据）要付 1–2 页元数据，占比偏高。
   这是页粒度的下界，只能靠"状态没变就不写（去重）"压缩，不打算再优化。
4. **快照预算**：`origins` 上限 = min(254 条, 4000 B)，短名 254 条封顶、16 字符名约 180 条；
   超出后新来源内联（每条约 +14 B）。极端场景（GUI 反复重连产生大量不同 origin）需实测。
5. **尾页重写是唯一"非追加"写**：实现纪律要求高（前缀从磁盘重读、只限最后一页、只在持锁时、
   失败即停录、不得推广到每批 flush）。已用 §12 五条用例兜住，但要收成单一 `rewriteTailPage()` 入口。
6. **重写失败即停录**：一次瞬时 I/O 故障会让录制直接停止，用户必须手动重开。这是"不掩盖故障"
   的代价，UI 必须显式提示，不能只写日志。
7. **去重依赖序列化稳定**：设置结构用 map 承载时序列化顺序会漂移，导致"永远不相等、永远写"。
   实现必须用 struct（字段顺序固定）。
8. **`keep_days` 不删坏头文件**：这是保守选择，代价是损坏文件永久堆积，需要用户手工清理。
9. **CoW 文件系统**（btrfs/ZFS）上重写会触发块重分配：一次 4 KB，可接受，但要实测确认不会退化成整文件快照。
10. **Unix 锁是 advisory**：无视 `flock` 的程序仍可并发写；`flock` 与 `fcntl` 互不可见。
11. **探测有竞态**：`locked` 是瞬时快照，探测与真正打开之间写者可能变化；Windows 上第三方以
    `share=READ` 打开时会把读者误报为写者。
12. **冷缓存打开 4 GB ≈ 4 s**：可接受，但频繁来回切大文件会觉得慢；v2 再评估文件内检查点。
13. **大 `flush_max_ms` 的时间窗口**：字节上界永远是 `batch_kb`（8 KB），但时间窗口 = 间隔；
    对 200 B/s 设 30 s，崩溃会丢约 6 KB（30 s）数据。有效间隔 = `min(flush_max_ms, batch_kb/速率)`，
    超过 30 s 对 200 B/s 已无意义（缓冲 41 s 先满）。
14. **`write()` 次数**在真实 NTFS 上的收益需实测（1.5 次/秒是理论值，含合包假设）。
15. **无 `clean` 位**：无法区分"崩在 flush 前（没有半条）"与"正常关闭"，只能靠尾部半条判定。
16. **记录区无逐条 CRC**：位翻转表现为数据错。若以后需要，可在文件内每 N KB 插一条聚合校验记录
    （成本约 4 B/N KB），但要新增记录类型，v1 不做。
17. **大文件导出**时间与内存（流式 + 进度事件）。
18. **「由文件开始」的参数预填**：槽里参数可能过时，连接前允许用户改。
19. **raw 载荷不可 grep**：人读依赖导出；若需外部工具直接解析，补一份 RFC 风格格式规范。
20. **头部固定 8 KB**：未来扩展靠 `slotVersion` 升版，不做"向前兼容地塞新字段进槽"。
21. **网络盘/压缩卷不支持写**：明确拒绝并提示，不做"尽力而为"。
22. **杀毒软件对 `FILE_SHARE_READ` 的处理**需真机实测。
